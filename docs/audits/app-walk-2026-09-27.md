# LYB iOS app walk — 2026-09-27

## Scope and evidence

Walked the signed-out surface, the authenticated onboarding fixture from welcome through first photo, both numeric and estimated body-fat branches, and the paywall separately through its existing StoreKit fixture. Also walked Home/Timeline, Stats, add-entry, photo selection, coach chat, and every Settings section on **LYB-Cert iPhone 17 Pro** (iOS 26.5). Screenshot receipts are outside the repository at `~/.codex/goals/lyb-app-walk/receipts/walk/`; they are not committed.

The brief's “12 steps” do not correspond to 12 unconditional pages in the current `OnboardingFlowViewModel.Step` flow. The authenticated fixture covers the manual-entry path through the first photo; the email-capture/account pages are skipped because that fixture already has an account email. The Apple Health confirmation page is conditional on granting HealthKit access, which was declined. Those paths remain unverified rather than inferred from the screenshots.

The app was bootstrapped with `JOVIE_AGENT_PROFILE=coder corepack pnpm ios:bootstrap-local-config` and built in Debug for the requested simulator. The terminal setup save called `http://localhost:3000/api/auth/mobile/profile`; no local API was listening. That failure is shown to the user and matches the existing terminal-save policy. I used the app's UI-test fixtures for authenticated Home/settings, the photo attach path, and StoreKit plans. Fixture behavior is not evidence of a live account, provider, purchase, or sync.

## P1 list and disposition

1. **Profile sign-out confirmation was unreachable.** Fixed by presenting the confirmation from the pushed Profile detail. Added `testProfileLogoutSignsOutFromPushedDetail`; it confirms the action and verifies the signed-out Apple wall.
2. **Talk acceptance is not verified.** Current `main` includes the Talk microphone in the coach composer behind training-coach and voice Statsig gates, but the local fixture did not expose it. A gate-enabled simulator session is needed to exercise the capture path; permission prompts were left untouched.
3. **BodySpec/Dexa import is not verified in this build.** The integration is implemented in source, but the local build reports it unavailable and no valid BodySpec provider account/configuration was present. The primary ICP in the brief requires this journey; verify it with valid credentials/config before claiming it works.

## Native-feel follow-up for W3

Settings and several entry/goal screens use custom full-page dark cards, bespoke back controls, menus, and modal sheets where native `Form`/`List`, `NavigationStack`, toolbars, `Picker`, and current Liquid Glass controls would be expected. The custom Home menu, timeline scrubber, and chat composer also need W3's IA/native-component pass. Native PhotosUI and system date/height wheels already appear. I did not observe a safe-area cutoff or persistent layout shift in the captured states; numeric keyboard accessories remained reachable.

## Auth, purchase, and data boundaries

- Apple sign-in was followed only as far as Apple's provider page; credentials were not entered. The app's local UI-test account fixture was used for authenticated screens and logout. Logout returned to the signed-out wall and the signed-out state remained after relaunch; real Apple-authenticated session persistence across relaunch remains unverified.
- The authenticated fixture skips pre-auth email capture/account creation, and the health confirmation step requires HealthKit authorization. These conditional paths were not exercised.
- The sign-out UI regression uses the existing synthetic UI-test account fixture, not a production account.
- The local API at `localhost:3000` was unavailable. It prevented a durable onboarding profile save and live coach reply.
- HealthKit authorization, a real RevenueCat purchase/restore, export delivery, account deletion, and authenticated Apple subscription management were not completed. The corresponding flows were inspected without granting new permissions, spending money, sending private data, or deleting an account.
