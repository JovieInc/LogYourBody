# LYB-37 priority sequencing slice

The existing default-off optimizer now reviews specialization order among remaining working sets. `sequencingContext` supplies an explicit block ID, observation timestamp, scoped muscle intents, optional concrete inventory and hard exclusions, muscle readiness, limitation observations and timestamped segments of one parent session. Unspecified goals remain unspecified. An active block preference overrides only the same muscle's persistent preference; expiry exposes the persistent goal again. These optimizer inputs are proposal observations, not a durable program revision or new enrollment authority.

Warm-up, completed work, user-edited order and reported limitations constrain priority order. The review includes each remaining set identity, completed-set IDs and timestamps, planned and observed qualitative demands, inspectable eligible alternatives and a sequencing decision contract. Target-muscle fatigue and grip/trunk/joint limitations remain separate. A canceled continuation is marked for unfinished-work reconciliation; this module does not allocate replacement volume or bank set debt. A new segment or date does not erase prior observations or certify recovery.

The small reviewed annotation set distinguishes lateral-raise side-delt targets from incline-press anterior-delt assistance. Legacy `shoulders` fractions remain volume-accounting conventions. They are not medial-delt fatigue measurements. The evidence qualification is based on [Nunes et al.](https://onlinelibrary.wiley.com/doi/10.1080/17461391.2020.1733672) and [Campos et al.](https://pmc.ncbi.nlm.nih.gov/articles/PMC7706677/): priority-first is a product default, not a universal hypertrophy superiority claim; acute activation is not calibrated fatigue transfer. `rule:priority-sequence-v1` identifies this bounded product policy. No new scientific numerical prescription or fatigue score is introduced.

The canvas accepts `order_priority` or the bounded utterance “Put side delts first” (also biceps, chest, upper chest, back or lats). It reuses the optimizer's policy and existing first-party canvas ledger. Submit/read never applies a proposal. Explicit apply, reject, stale-base checks and undo retain the existing ledger semantics. Ordering preserves all approved sets and goals. The canvas execution readback follows the saved order. Native submit/propose/decide requests now retain a UUID across lost-response retries; legacy clients that omit it keep their existing behavior.

The optimizer certifier compares the complete ordered diff, findings, tradeoffs, narration, source identity and decision contracts against a fresh deterministic evaluation. An authenticated optimizer acceptance still has `writesPerformed: false`. It must not be presented as a saved program change. The canvas is the durable reorder path in this slice. Existing coach/API/canvas gates remain default off; no rollout, schema migration or MCP change is included.

## Remaining acceptance

This slice does **not** close LYB-37. The enrolled workout service still builds the legacy baseline independently of the canvas. Binding an applied scoped revision to future prescriptions, swaps and adaptation needs the canonical training admission/concurrency boundary; it must preserve active and completed prescription snapshots. Durable constraint policies, bounded allocation proposals, schedule/duration feasibility, rolling 7/14-day accounting, LYB-174 reconciliation and contracts for the other programming variables remain separate work. There is no claim of native full-loop shipment or certification.
